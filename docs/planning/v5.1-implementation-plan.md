# V5.1 Implementation Plan — Porting Gaps

Based on `docs/planning/v5-porting-audit.md`. Eight new phases to reach 100% parity with V3/V4.

---

## Phase Overview

| Phase | Name | Goal | Depends On | Est. Time |
|---|---|---|---|---|
| **9** | V4 Analytics Web Pages | 4 analytics pages + 14 components ported to V5 React app | Phase 4 | 2–3 sessions |
| **10** | SAM.gov DBWD Refresh | Live DBWD rate refresh from SAM.gov WDOL API | Phase 6 | 1–2 sessions |
| **11** | Redis Caching & SSE Hardening | DBWD rate cache + SSE consumer group + connection management | Phase 6 | 1 session |
| **12** | DuckDB Archive Integration | Wire DuckDB store into analytics API, Parquet archive views, init script | Phase 6 | 1–2 sessions |
| **13** | Integration Test Infrastructure | Cross-service integration tests with real PostgreSQL and Redis | Phase 5 | 2–3 sessions |
| **14** | Golden-Set Expansion | 100+ examples, edge cases, regression thresholds | Phase 7 | 1–2 sessions |
| **15** | Trust Score Reconciliation | Align TypeScript and Python weight to single source of truth | Phase 4 | 1 session |
| **16** | Final Polish & Hardening | Docker images, seed scripts, migration consolidation, trust score ADR | Phase 8 | 1 session |
